Customer Product Review API (Mobile)
Product ratings and reviews, as JSON, for the mobile apps.
Controller: src/controllers/api/CustomerReviewController.ts
Base path: /api/customer/reviews
Content type: application/json (no file uploads on this module — see §7)

Not the same as /api/review/*. An older controller
(src/controllers/api/ReviewController.ts) exposes just two routes —
GET /api/review/product/:product_id and POST /api/review/create — and is left in
place for backwards compatibility. New mobile work should use the routes here.
See Appendix B.

5. Error format
Identical to the support ticket API — three shapes, depending on which layer rejected:
CodeShapeBodyWhen403





API-key





{"status":"error","data":"You do not have permission…"}





Bad/missing access-key, wrong length, wrong store, or Accept not application/json.





401





auth





{"error":"Unauthorized"}





Missing/expired customer token on a protected route.





403





auth





{"error":"Forbidden"}





Valid token, but not a customer.





400/404





controller





{"success":false,"message":"…"}





Everything in §4.








Plain Text








const msg = body.message ?? body.error ?? body.data ?? "Something went wrong";


The two 403s mean opposite things — data = the app's API key is misconfigured (don't log
the user out), error = wrong user type. Tell them apart by which key the body carries.



6. Typical app flow


Plain Text








Product detail screen (logged out or in)
  GET  /api/customer/reviews/product/{pid}/summary     → stars on the card
  GET  /api/customer/reviews/product/{pid}?page=1      → review list


Logged in, on the product page
  GET  /api/customer/reviews/product/{pid}/mine        → 200 = "Edit yours", 404 = "Write one"


Write / change
  POST /api/customer/reviews                           → 201 new, 200 replaced
  PATCH /api/customer/reviews/{id}                     → tweak
  DELETE /api/customer/reviews/{id}


Account → My reviews
  GET  /api/customer/reviews
  GET  /api/customer/reviews/pending                   → "rate your purchases" nudge


Notes for the client
Every write returns product_rating, so update the product screen from the response instead
of re-fetching the summary.
POST is an upsert. Don't build a separate "already reviewed?" guard around it — call
/mine only when you need to pre-fill the form.
Reviews go live immediately (approved), so the new review will be in the next list call.




7. No photo reviews
Unlike support tickets, reviews have no attachment support. The ProductComment model has
no image field, so there is nothing to upload to. All review endpoints are plain JSON.
If photo reviews are wanted, that needs a schema change first (an image ref on
ProductComment, like SupportTicket.image) — tell me and I'll add it across the model,
controller and this doc.



Appendix A — cURL


Bash








BASE="https://mystore.com"
TOKEN="eyJhbGciOi..."
KEY="0f3c9a1b7e2d4c8a6b5f0e9d3c7a1b4e8f2d6c0a9b3e7f1d"
PID="66f0aabbccddeeff00112233"


PUB=(-H "access-key: $KEY" -H "Accept: application/json")
AUTH=("${PUB[@]}" -H "Authorization: Bearer $TOKEN")


# Public — summary + list
curl -s "${PUB[@]}" "$BASE/api/customer/reviews/product/$PID/summary"
curl -s "${PUB[@]}" "$BASE/api/customer/reviews/product/$PID?page=1&sort=highest"


# Only 1-star, verified purchases
curl -s "${PUB[@]}" "$BASE/api/customer/reviews/product/$PID?rating=1&verified=true"


# Mine
curl -s "${AUTH[@]}" "$BASE/api/customer/reviews"
curl -s "${AUTH[@]}" "$BASE/api/customer/reviews/pending"
curl -s "${AUTH[@]}" "$BASE/api/customer/reviews/product/$PID/mine"


# Create / update
curl -s -X POST "${AUTH[@]}" "$BASE/api/customer/reviews" \
  -H "Content-Type: application/json" \
  -d "{\"product_id\":\"$PID\",\"rating\":4,\"comment\":\"Good quality.\"}"


# Edit
curl -s -X PATCH "${AUTH[@]}" "$BASE/api/customer/reviews/66f2c1d4e5a6b7c8d9e0f1a2" \
  -H "Content-Type: application/json" \
  -d '{"rating":5}'


# Delete
curl -s -X DELETE "${AUTH[@]}" "$BASE/api/customer/reviews/66f2c1d4e5a6b7c8d9e0f1a2"

Two behaviour notes on the old controller, if you keep using it:
Its create uses AuthGuards.requireAuth(), which accepts any authenticated user type,
not just customers — an owner token can post a product review through it.

address would overwrite each other's review; this controller keys on customer_id instead.
